# Deployment

## Build Artifacts

| Artifact | Format | How to build |
|----------|--------|--------------|
| WASM browser engine | `web/pkg` npm-style package generated by wasm-pack | `cd monitor-client && wasm-pack build --target web --out-dir ../web/pkg --release` |
| Frontend bundle | Static HTML/CSS/JS assets in `web/dist` | `cd web && npm ci && npm run build` |
| Backend proxy | Native Rust binary | `cargo build --release --bin monitor-proxy` |

## Packaging

No Dockerfile, compose file, package manifest, systemd unit, or Kubernetes manifest is checked in. The README describes a manual deployment model:

1. Build the WASM engine first because the Vue app depends on `web/pkg`.
2. Build the Vue static bundle into `web/dist`.
3. Build and run the `monitor-proxy` release binary.
4. Put a web server such as Nginx or Caddy in front of static files and backend routes when deploying separately.

## Environments

| Environment | URL / target | Promotion from | Notes |
|-------------|--------------|----------------|-------|
| Local frontend | Vite dev server | N/A | Requires prior wasm-pack build and optional `VITE_API_BASE`. |
| Local backend | `http://localhost:3080` by default | N/A | Requires `DATABASE_URL`; use `--debug` for permissive local CORS. |
| Production | Operator-defined host | Local/release build | Requires explicit `--allowed-origin` unless `--debug` is used. |

## Runtime Configuration

| Setting | Source | Default / requirement |
|---------|--------|-----------------------|
| `DATABASE_URL` | CLI/env via Clap | Required by current `Config`. Example: `sqlite://data.db?mode=rwc`. |
| `--host` | CLI | `0.0.0.0` |
| `--port` | CLI | `3080` |
| `--cache-dir` | CLI | `$HOME/.cache/hsn-phira` |
| `--api-base` | CLI | `https://phira.5wyxi.com` |
| `--mp-server` | CLI | `localhost:12346` |
| `--allowed-origin` | CLI | Required in non-debug mode. |
| `VITE_API_BASE` | frontend env | Empty means same-origin API calls. |

## Health Checks

| Check | Endpoint / command | Expected |
|-------|--------------------|----------|
| Backend process | Start `monitor-proxy` with valid `DATABASE_URL` and required CLI flags | Process binds configured host/port and logs listening address. |
| HTTP smoke test | `GET /rooms/info` | JSON response or service-level error if Phira multiplayer dependency is unavailable. |
| Frontend static files | Browser load of deployed `web/dist` | Vue app renders player/monitor tabs and downloads WASM package assets. |

No dedicated `/health` or `/ready` endpoint exists.

## Monitoring & Alerts

No monitoring, alerting, metrics, or tracing configuration is checked in. Current observability is standard logging through `env_logger` on the backend and browser console output in frontend/WASM paths.

## Rollback Procedure

No automated rollback procedure is checked in. For manual deployments, keep the previous backend binary, previous `web/dist` bundle, and compatible database backup available; restore those artifacts and restart the process or reverse proxy if a release fails.
